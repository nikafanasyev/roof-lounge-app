# Roof Lounge — Telegram Mini App

Рабочий скелет продукта из `roof-lounge-app-architecture.md` (лежит в проекте Roof Lounge): операционка персонала (смены, поломки, задачи), QR-сценарии гостя за столом и модуль вкусового профиля/миксов — то, что не покрывает Quick Resto.

## Что уже готово

- `apps/miniapp` — Telegram Mini App (React + Vite + TS). Все экраны работают **на моковых данных в памяти** (`src/data/seed.ts`) — приложение можно открыть и пройти все сценарии прямо сейчас, без единой настройки.
- `apps/bot` — скелет Telegram-бота (grammY): команда `/start` открывает мини-апп, плюс подписка на новые QR-вызовы через Supabase Realtime с уведомлением персоналу в чат.
- `supabase/migrations/0001_init.sql` — SQL-схема БД: гости, справочник вкусов, миксы, состав миксов, оценки, столы, QR-вызовы, лист ожидания, потерянные вещи, смены, поломки, задачи.

## Что показывает прототип

- **Персонал → Гости**: поиск гостя → вкусовой профиль (шкалы предпочтений, средняя крепость, любимые миксы) → история миксов → сборка нового микса (бренд → вкус → доли в % → оформление).
- **Персонал → Смена**: чек-лист открытия/закрытия, передача смены заметкой.
- **Персонал → Проблемы**: фиксация поломки, статус, сколько дней открыта.
- **Персонал → Задачи**: постановка и отметка выполнения.
- **Руководитель → Сводка**: счётчики + автоматические предупреждения (пропущенный чек-лист, зависшая проблема, вызов без реакции).
- **Руководитель → Вызовы**: лента QR-вызовов со столов, время реакции.
- **Гостевой QR-экран** (`/table/:token`, отдельный маршрут без нижней навигации): «позвать сотрудника» / «попросить счёт» / «нужна помощь» / «оставил вещь».

## Как запустить локально

```bash
cd apps/miniapp
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Вне Telegram (обычный браузер) SDK деградирует в заглушку — вёрстка и все сценарии работают, просто без реальных Telegram-данных пользователя.

Гостевой экран: `http://localhost:5173/table/table-7` (номер стола зашит в токен для демо).

## Что нужно от тебя, чтобы пойти дальше

1. **Проект в Supabase** (supabase.com, есть бесплатный тариф) — после создания:
   - выполнить `supabase/migrations/0001_init.sql` (через SQL Editor в дашборде или Supabase CLI);
   - взять `Project URL` и `anon public key` → в `apps/miniapp/.env` (см. `.env.example`);
   - взять `service_role key` → в `apps/bot/.env` (см. `apps/bot/.env.example`) — этот ключ не должен попасть в мини-апп/фронтенд.
2. **Токен Telegram-бота** от @BotFather (`/newbot`, если бота ещё нет) → `BOT_TOKEN` в `apps/bot/.env`.
3. **Публичный URL мини-аппа** после деплоя (см. ниже) → `MINI_APP_URL` в `apps/bot/.env`, и туда же указать этот URL в настройках бота через @BotFather (`/mybots` → Bot Settings → Menu Button или Mini App).
4. **ID чата персонала** (группа в Telegram, куда должны падать уведомления о QR-вызовах) → `STAFF_CHAT_ID`.
5. **Доступ к API Quick Resto** — открытый вопрос из архитектурного документа (раздел 1.2): если у Roof Lounge есть интеграционный модуль Quick Resto, сводку руководителя можно будет пополнить выручкой/средним чеком автоматически.

После этого data/repo.ts в мини-аппе нужно переписать на реальные вызовы `@supabase/supabase-js` — сигнатуры функций специально сделаны такими, чтобы экраны их не заметили.

## Деплой (ориентир, см. раздел 3 архитектурного документа)

- **apps/miniapp** → Vercel (или Netlify): `npm run build`, раздать `dist/`.
- **apps/bot** → Railway (или любой сервис с постоянным процессом — боту нужен long-polling или webhook, статический хостинг не подойдёт).
- **QR-коды на столах** — каждый ведёт на `https://t.me/<bot_username>/<app_name>?startapp=table_<N>`, где `<N>` — номер стола (генерация самих QR-картинок — отдельный маленький скрипт, не входит в этот скелет).

## Структура репозитория

```
apps/
  miniapp/   — Telegram Mini App (гость, персонал, руководитель)
  bot/       — Telegram-бот (grammY) + уведомления персоналу
supabase/
  migrations/ — SQL-схема БД
```
